How it works

  1. Keep skills in a registry

    A registry is a plain git repository of Agent Skills, grouped in namespaces like frontend or backend. Review skills like any other code.

  2. Install them in each project

    mestiere add frontend copies the skills into .agents/skills/ and locks each one to a registry commit in skills.yaml.

  3. Every agent sees them

    Codex, Gemini CLI, Cursor and Copilot read .agents/skills/ directly; Claude Code and Kiro get links in their own folders. Teammates and CI run mestiere sync and get the same files.

Quick start

Install skills in a project

mestiere init --agents claude,kiro
mestiere registry add polarity git@github.com:polarity-dev/skills.git
mestiere add frontend backend/db-migrations
git add skills.yaml .gitignore
git commit -m "Add team skills"

A teammate who clones the repository runs mestiere sync.

Read the getting started guide

Publish skills in a registry

mkdir skills && cd skills && git init
mestiere registry init --name polarity
mestiere registry new-namespace frontend --description "Frontend practices"
mestiere registry new-skill frontend/forms --description "Build accessible forms"
mestiere registry lint

Push it, and any project can add it.

Why mestiere

Mestiere is Italian for craft: the know-how a workshop hands from one person to the next. mestiere does that for coding agents.

  • One source of truth

    Skills live in a git registry, public or private, reviewed like any other code.

  • Organized by namespace

    Install a whole namespace or a single skill. New skills in an installed namespace arrive on the next update.

  • Reproducible

    Every install is locked to a registry commit and a content hash. Teammates and CI get byte-identical skills.

  • Every agent at once

    Files live once in .agents/skills/, which Codex, Gemini CLI, Cursor and others read directly. Claude Code and Kiro get symlinks to it.

  • Out of your way

    Installed skills are ignored by git by default. Your own skills sit next to them untouched, and committing any skill is one command.

  • Safe by construction

    mestiere replaces a folder only when it can prove it's an unmodified copy of a published skill. See the safety model.

  • No lock-in

    Registries are plain git repositories. Installed skills are plain folders that follow the Agent Skills spec.

  • Your git, your auth

    mestiere runs the system git, so SSH keys, credential helpers and gh auth just work.

Or let your agent set it up

The Homebrew install also gives Claude Code and Kiro mestiere's own skills, for every project on your machine. Then ask your agent, from any repository:

Set up mestiere for this repo with our registry git@github.com:polarity-dev/skills.git

The agent runs mestiere init, shows you what the registry offers, installs the skills that fit the codebase and commits skills.yaml. Later prompts work the same way: "Are any of our skills outdated? Update them and summarize what changed".

Installed another way? Run mestiere add -g mestiere once. Agents that read the web can start from llms.txt.
