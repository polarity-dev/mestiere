Come funziona

  1. Tieni le skill in un registry

    Un registry è un normale repository git di Agent Skills, raggruppate in namespace come frontend o backend. Revisiona le skill come qualsiasi altro codice.

  2. Installale in ogni progetto

    mestiere add frontend copia le skill in .agents/skills/ e blocca ognuna su un commit del registry in skills.yaml.

  3. Ogni agente le vede

    Codex, Gemini CLI, Cursor e Copilot leggono .agents/skills/ direttamente; Claude Code e Kiro ricevono link nelle proprie cartelle. Colleghi e CI eseguono mestiere sync e ricevono gli stessi file.

Avvio rapido

Installa le skill in un progetto

mestiere init --agents claude,kiro
mestiere registry add polarity git@github.com:polarity-dev/skills.git
mestiere add frontend backend/db-migrations
git add skills.yaml .gitignore
git commit -m "Add team skills"

Un collega che clona il repository esegue mestiere sync.

Leggi la guida Primi passi

Pubblica le skill in un registry

mkdir skills && cd skills && git init
mestiere registry init --name polarity
mestiere registry new-namespace frontend --description "Frontend practices"
mestiere registry new-skill frontend/forms --description "Build accessible forms"
mestiere registry lint

Fai il push, e qualsiasi progetto può aggiungerlo.

Scopri come creare un registry

Perché mestiere

Il mestiere è il saper fare che una bottega passa da una persona all'altra. mestiere fa lo stesso per gli agenti di programmazione.

  • Una sola fonte di verità

    Le skill vivono in un registry git, pubblico o privato, revisionato come qualsiasi altro codice.

  • Organizzate per namespace

    Installa un intero namespace o una singola skill. Le nuove skill di un namespace installato arrivano al prossimo aggiornamento.

  • Riproducibili

    Ogni installazione è bloccata su un commit del registry e un hash del contenuto. Colleghi e CI ricevono skill identiche byte per byte.

  • Tutti gli agenti insieme

    I file vivono una sola volta in .agents/skills/, che Codex, Gemini CLI, Cursor e altri leggono direttamente. Claude Code e Kiro ricevono symlink verso di essa.

  • Non ti intralcia

    Le skill installate sono ignorate da git per impostazione predefinita. Le tue skill restano accanto a loro intatte, e fare il commit di una skill richiede un solo comando.

  • Sicuro per costruzione

    mestiere sostituisce una cartella solo quando può dimostrare che è una copia non modificata di una skill pubblicata. Vedi il modello di sicurezza.

  • Nessun lock-in

    I registry sono normali repository git. Le skill installate sono normali cartelle che seguono la specifica Agent Skills.

  • Il tuo git, la tua autenticazione

    mestiere usa il git di sistema, quindi chiavi SSH, credential helper e gh auth funzionano senza altro.

Oppure fallo configurare al tuo agente

L'installazione con Homebrew dà anche a Claude Code e Kiro le skill di mestiere, per ogni progetto sulla tua macchina. Poi chiedi al tuo agente, da qualsiasi repository:

Configura mestiere per questo repo con il nostro registry git@github.com:polarity-dev/skills.git

L'agente esegue mestiere init, ti mostra cosa offre il registry, installa le skill adatte al codice e fa il commit di skills.yaml. I prompt successivi funzionano allo stesso modo: "Qualcuna delle nostre skill è obsoleta? Aggiornale e riassumi cosa è cambiato".

Hai installato in un altro modo? Esegui una volta mestiere add -g mestiere. Gli agenti che leggono il web possono partire da llms.txt.
